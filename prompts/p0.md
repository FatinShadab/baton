Build a VS Code extension called "Baton" (TypeScript) for a hackathon MVP.
Speed matters more than polish. No tests unless asked. No frameworks in the webview (vanilla HTML/CSS/JS).

What it does: the user types or speaks a coding task in a sidebar. A router
(Gemma 4 via Google AI Studio, fallback Gemma via Ollama Cloud, fallback
rules) returns a JSON route: task type, risk tier, destination, reason. A
deterministic policy gate can only raise risk, never lower it. The user can
(a) open ChatGPT/Gemini with a context-rich prompt copied to the clipboard and
paste the plan back, or (b) run the task in Codex CLI (`codex exec`) in a VS
Code terminal after confirmation. Results and plans are saved to local memory.

Constraints:
- Use esbuild to bundle. Node 18+ APIs (global fetch, FormData, Blob).
- Keys live in context.secrets (SecretStorage), never in settings or files.
- Persistent data: JSON files under context.globalStorageUri.
- Never read or send .env, *.pem, *.key, id_rsa*, credentials*, node_modules, .git.
- Keep files small, one responsibility each: src/{extension,types,secrets,store,
  router/{rules,gemma,ollama,index},policy,context,memory,handoff,voice,codex}.ts
  and media/{panel.html,panel.js,panel.css}.
- Every external call has a timeout and a try/catch; failures fall through, never crash.
